# Condition familiarity: pilot methodology v0.1

This system estimates whether Vietnamese Y4–Y6 general medicine students recognize a condition and understand its usual presentation and basic mechanism. It does not measure clinical competence, disease severity, or the difficulty of an individual puzzle. All weights, thresholds and reference scores below are hypotheses pending human evaluation. No live game ratings have been changed.

## Repository fit

The game has 400 conditions in `cases.csv`, identified by numeric case ID, with a Vietnamese diagnosis and accepted aliases. `revision-data.json` adds 16 overlapping specialties and a separate treatment puzzle. `case-difficulty.json` supplies a 1–5 editorial `hardness`; `app.js` uses it for weighted sampling at each selected difficulty. All conditions remain eligible. The private `.internal/case-hardness-review.json` records the existing editorial judgments. The Google-frequency utilities collect an unrelated visibility proxy and do not alter game ratings.

There was no reusable LLM provider, agent runner, model configuration or API dependency in the repository. The proof of concept therefore uses existing Deno tooling and native Luna/Terra subagents through versioned file handoffs. The command-line tool prepares packets, validates responses, scores them, caches artifacts, compares pairwise responses, and evaluates reference agreement. It does not make network calls or claim that a model was executed merely because a packet was created. Native agent execution is recorded separately in the pilot report. No package dependencies were added.

## Rubric and score

Each dimension has five ordinal levels, 0 (most familiar) through 4 (least familiar). The authoritative, versioned definitions are in [`rubric.json`](../scripts/difficulty/rubric.json). The units are ordinal design choices, not validated linear distances or probabilities.

| Dimension | Weight | Measurement and evidence priority |
|---|---:|---|
| Curriculum prominence | 35 | Disease-specific undergraduate objectives, clinical problem lists and expected learning depth, triangulated across institutions and cohorts. Specialty course titles alone cannot establish disease coverage. |
| Clinical exposure | 25 | Student encounter logs, clerkship case requirements, bedside teaching and rotation audits. Hospital case mix is a proxy; national prevalence is a weaker contextual proxy. Record season, hospital level and region. |
| Teaching/exam reinforcement | 20 | Dedicated undergraduate chapters, lecture schedules, required readings and verified assessment blueprints. Count independent teaching opportunities, not duplicate files or web search hits. Distinguish repeated reinforcement from simply being listed in a curriculum. |
| Canonical pattern familiarity | 10 | Whether students know the standard syndrome and basic mechanism. Ideally measure with a standardized short assessment. A memorable rare disease may score low. Do not inspect the game's clues. |
| Generalist recognition scope | 10 | Whether recognition/basic understanding is expected of a generalist, a core specialty student, or a subspecialist. Difficult treatment is irrelevant if recognition is basic undergraduate knowledge. |

For curriculum, level 0 requires repeated explicit core objectives across at least two undergraduate programmes; level 1 is an explicit required topic/core problem in one programme; level 2 is limited depth or documented variation; levels 3–4 require positive evidence of advanced/subspecialty scope. No search result is not evidence of curricular absence. For other dimensions, 0 means repeated/broad familiarity, 1 usual/core specialty familiarity, 2 variable or occasional familiarity, 3 predominantly specialist familiarity, and 4 niche familiarity; use the dimension-specific definitions in the JSON.

For dimensions C/E/R/P/S, calculate `D = (35*C + 25*E + 20*R + 10*P + 10*S) / 4`. Higher is harder, on 0–100. Use the unrounded score for tiering; display a value rounded to five. Initial boundaries are **Easy ≤30; Medium >30–60; Hard >60**. These represent familiarity bands, never equal-sized quantiles. They must be calibrated with humans before adoption. A score of 60 is not a 60% probability of failure. Close scores should be treated as effectively tied, not a precise ordering.

The five dimensions are correlated. Curriculum gets the largest weight because it matches the target construct; exposure is next because rotations build recognition; reinforcement helps distinguish merely listed material from repeated learning. Pattern and scope supply smaller corrections. These weights are architectural judgments, not empirically established Vietnamese coefficients. Compare against simpler curriculum-only and equal-weight baselines, ablate each component, and fit at most a small number of constrained parameters on the calibration split. If reinforcement/scope add no held-out value, reduce or remove them rather than double-counting education.

Every dimension includes a value, `basis`, supplied evidence IDs and a rationale:

- `evidence_backed`: a verified, condition-specific and dimension-specific source supports the assigned level. This still involves coding judgment and does not prove national student familiarity.
- `llm_estimate`: an explicitly tentative model/editorial prediction. It cannot masquerade as a curriculum fact or observed encounter rate.
- `unknown`: null, with an explanation. No source found never becomes level 4.

Unknown dimensions use level 2 **only for a provisional point estimate**; the original null remains in the data. We never redistribute missing weight, which could make incomparable conditions look equally well supported. Sensitivity bounds allow unknowns to span 0–4, estimates ±1 level and supported judgments ±0.5, clipped to 0–4, then propagate through the weighted sum. These are design sensitivity ranges, not statistical confidence intervals. Evidence coverage is the sum of weights with directly supported dimensions, not a probability of accuracy. Never use the midpoint of a mostly missing assessment as a release-ready classification.

## Research findings and source limitations

[HMU's undergraduate LMS](https://lms.hmu.edu.vn/course/index.php?categoryid=64) links its [2026 core clinical-problem document](https://drive.google.com/file/d/1UWAiF19Bt4dGNxyIgGi0DJyScsVjHLgh/view). The downloaded PDF was text-extracted and relevant table pages visually checked. It distinguishes primary and secondary learning depth, with year columns. Dengue and tuberculosis appear under secondary topics; appendicitis, DKA, pulmonary embolism and pre-eclampsia have primary-topic entries. Those depth markers are not familiarity labels. The new programme's applicability to current cohorts needs confirmation.

[Phạm Ngọc Thạch's course list](https://ky.pnt.edu.vn/vi/de-cuong-chi-tiet-hoc-phan-2005/de-cuong-chi-tiet-hoc-phan-2739) lists clinical medicine, surgery, obstetrics and paediatrics across clinical years, plus a dedicated tuberculosis course. It provides institutional context, not disease-by-disease exam frequencies. These sources support curriculum-first investigation but do not validate our numerical weights.

[HMU's textbook catalogue](https://dulieuso.hmu.edu.vn/handle/hmu/170?locale=vi) identifies a Vietnamese infectious-disease text intended partly for medical students. Its full text is restricted, so no uninspected chapter is claimed as evidence. A Tây Nguyên curriculum PDF surfaced disease-specific objectives in search, but full retrieval failed; it remains an unverified lead and contributes no supported score. No verified nationwide undergraduate examination blueprint, audited rotation logs, or representative familiarity survey was obtained in this pilot. These gaps must remain visible.

Prioritize current undergraduate disease objectives from multiple northern/southern/central schools, then actual required textbook chapters and course assessment objectives. Residency entrance syllabi are supplementary evidence with a different target population. The inspected [2023 Ministry dengue guideline](https://benhvienhatrung.vn/wp-content/uploads/2023/07/Quyet-dinh-so-2760QD-BYT-ngay-0472023.pdf) has national clinical-facility scope, which cannot independently establish undergraduate teaching, encounters, or student mastery. The [WHO Viet Nam profile](https://data.who.int/countries/704) and [TB survey-method discussion](https://www.who.int/teams/global-programme-on-tuberculosis-and-lung-health/tb-reports/global-tuberculosis-report-2025/tb-disease-burden/1-4-national-tb-prevalence-surveys) are useful burden proxies, with measurement limitations. Population incidence does not equal exposure at a teaching hospital. These contextual sources contribute no supported dimension scores in this pilot. Never cite the mere existence of a guideline as proof a topic is taught. The private `SOURCE-APPRAISAL.md` records accessible material and exclusions.

Do not weight Google hit counts. Give Wikipedia pageviews **0% baseline weight**. [Wikimedia documents pageview counting and bot categories](https://doc.wikimedia.org/generated-data-platform/aqs/analytics-api/concepts/page-views.html); redirects can be counted separately from the target. Vietnamese-language readers are not specifically Vietnamese medical students. Pageviews can reflect news, celebrity interest, general-public anxiety and naming/coverage differences. For a future ablation, resolve Wikidata entity and Vietnamese article/redirects, use a fixed 12-month window and human-traffic category, retain missing articles as missing, and log transforms/outlier sensitivity. Test incremental held-out prediction beyond the rubric, including news-window exclusion. Add at most a small capped component only after demonstrated improvement; do not add popularity merely because it is easy to collect.

## Reference conditions and calibration

The private research directory `.internal/condition-difficulty/` contains 42 representative candidates, including common internal medicine, surgery, paediatrics, obstetrics, emergency, tropical, dermatological, eye, ENT and psychiatric conditions. `REFERENCE.md` is the readable table; `reference.json` preserves all dimension levels, exact/raw and rounded scores, rationales, aliases, source locators, sensitivity ranges and review state. There are 22 proposed Easy, 16 Medium and 4 Hard seeds; this distribution is a consequence of the sample, not a quota. Every candidate is `humanReview: null` and `anchorApproved: false`. They are provisional reference **candidates**, not a gold benchmark or validated anchors.

Counterexamples deliberately include cholera/tetanus/epiglottitis (limited encounters can coexist with memorable teaching), phaeochromocytoma/Kawasaki/anti-GBM disease (classic patterns versus depth of understanding), melioidosis/scrub typhus/thalassaemia (local and regional relevance), and cystic fibrosis (international model priors may transfer poorly). Uncertainty is part of the target, not noise to conceal. Scores should be reviewed especially when the clinical entity is more specific than a source's broad heading.

Recruit at least two clinical teachers and students from Y4, Y5 and Y6 across at least two schools/regions for initial adjudication; a practical starting panel is two teachers and three students per year. Give independent reviewers the **blinded** `human-review.csv`, without seed/model scores, and randomize disease order. Ask for familiarity (0 well understood through 4 unknown), standard syndrome/basic-mechanism checks, proposed tier, year, school and rotation completion. Use disease-neutral standardized questions rather than current game clues. Define expected knowledge before marking answers. Teachers should establish expected curricular scope; students should establish actual familiarity. An authoritative course list is not a substitute for student performance.

Publish disagreement distributions and year/rotation stratification internally before adjudication. Resolve ambiguous entities and contested middle cases with documented reasons; allow unresolved/tied labels. Use equal Y4/Y5/Y6 weighting initially, then predeclare a different population mix only if the audience warrants it. Choose about 24 candidates for calibration and 18 for untouched evaluation, stratified by specialty/tier and grouping related entities together. This small holdout diagnoses gross failure; it cannot certify each of 16 specialties. Confirm on a fresh 100–200-condition, school-diverse reference sample before bulk rollout. Student/item sample sizes should be refined from pilot variance, not asserted as already adequate.

After adjudication, select 2–3 stable anchors per tier, distributed across specialties, with scores/ranges and human sign-off. Do not select anchors merely because a model agrees with our seed. Freeze them and the thresholds before held-out evaluation. Changing the rubric, prompts, sources or anchors invalidates relevant caches and requires a new run.

## Model workflow and pairwise comparisons

The requested Sol/Luna/Terra allocation is a testable workflow hypothesis, not a demonstrated accuracy ordering. [Official model guidance](https://developers.openai.com/api/docs/models) identifies these model families, but does not establish that Terra is better at Vietnamese medical familiarity. Actual native subagent model IDs in this experiment are `gpt-6-luna` and `gpt-6.1-terra`, reasoning `medium`; model availability/prices must be checked for a future API deployment. Sol coordinates the rubric and reviews evaluation failures; human Vietnamese reviewers own the reference.

1. **Resolve identity.** Stable case IDs anchor the current bank. Carry the exact Vietnamese entity plus supplied English aliases. Accent/punctuation normalization helps lookup only; it must not merge subtypes, parent diseases, complications, or ambiguous abbreviations. Use explicit terminology mappings and reviewer-approved external IDs before deduplicating at scale. Preserve original names. Quarantine alias collisions and scope mismatches. Never use the ICD code alone as clinical identity.
2. **Freeze evidence.** Retrieve disease-specific material once, record institution/cohort/date/page, retain a short claim/excerpt and document hash, and attach only relevant evidence to each condition. Retrieve new evidence before paying another model to re-guess missing facts. The planner refuses identities, aliases or specialty tags that are stale against the live bank.
3. **Calibrate Luna.** Use the supplied production prompt and strict schema with approved anchors. Start with batches of 8–12 mixed conditions, several specialties and fixed anchor reminders. Keep per-condition explanations short. Avoid a disease's clues, existing hardness, Google counts and seed target labels. No approved anchors existed in this exploratory run, so packets correctly supplied an empty anchor list.
4. **Check automatically.** Reject missing/duplicate IDs, malformed/null rules, invented or out-of-scope citations and unsupported evidence-backed levels. Source verification remains a curator task: schema validity does not prove a source was correctly interpreted. Score outside the LLM. Preserve raw responses and refuse to overwrite a changed result under the same cache key; a repeat gets a distinct run ID.
5. **Repeat selectively.** During calibration repeat all cases in shuffled/reversed batch order. Once validated, repeat a stratified 10% plus flagged cases. Flag a raw-score difference >10, tier change, any dimension difference ≥2, source conflict, identity uncertainty, low evidence coverage, a sensitivity range spanning tiers, or a score within five of a boundary. Self-reported confidence cannot clear any flag. Audit at least 5% of otherwise accepted cases to detect confident systematic errors.
6. **Pairwise calibration.** Compare flagged cases with two nearby, human-approved anchors, plus some clearly distant control pairs. Ask which is more familiar, with tie and insufficient-evidence options. Use reversed-order independent calls for boundary cases and a stratified audit of the rest. Detect reversals and cycles in the comparison graph. Avoid all-pairs cost: a few anchor comparisons per flagged item are linear in the number of flagged items. A future anchored Bradley–Terry model can aggregate sparse comparisons with ties; fix anchor locations so batches share a scale and never force unresolved pairs into a fine total ordering.
7. **Escalate selectively.** Supply Terra an evidence-identical blind assessment first, then the specific disagreements for adjudication. Include source-poor regional conditions, alias/subtype problems, repeat disagreement, anchor contradictions and cross-tier conflicts. Terra may request source/human review; do not average the two models automatically. Audit some unflagged cases with Terra too, or routing quality cannot be estimated. Pairwise evidence from both orientations must be compared by condition identity, not answer letter.

Pairwise ranking may reduce scale drift but adds calls, position sensitivity and possible cycles. [A primary study of LLM judging](https://arxiv.org/abs/2406.07791) found position effects across pairwise and listwise tasks. This motivates reversed-order checks; it does **not** establish performance for disease familiarity. Compare absolute-only, pairwise-anchor-only and hybrid methods on the same human holdout, evidence budget and model effort. Evaluate close and distant pairs separately. A highly consistent ranking can still be systematically wrong.

Plans hash the rubric, prompt text, schema, pipeline version, model/effort, run ID, entity/alias list, evidence packet and source metadata. Results are content-addressed and immutable. Preserve the exact model/snapshot returned by the transport when available, timestamps, batch order, retry history and input/output/reasoning token usage. Native subagent tools did not expose billing usage, so pilot cost is explicitly unknown; no fabricated savings or dollar totals. Reproducibility means replayable inputs and preserved outputs, not guaranteed byte-identical future LLM responses. CLI plans do not themselves pin unavailable provider snapshots.

## Evaluation and rollout gate

Compare (A) Luna absolute only, (B) Luna with selective pairwise anchors, (C) Luna plus routed Terra, (D) all-Terra, and the existing editorial ratings as a historical baseline with a **predeclared** 1–5 to 3-tier mapping. Give model arms identical batches, order schedules, reasoning effort and source packets; test retrieval improvements separately from model improvements. The exploratory Terra subset used a different batch size, so it cannot isolate a model effect. Do not rank models using their agreement with one another or with LLM-generated targets.

Report exact tier agreement, a 3×3 confusion matrix, severe Easy↔Hard errors, quadratic-weighted Cohen kappa, Spearman correlation with tied ranks, and human-labeled pairwise agreement with ties/abstentions reported separately. Also report repeat/order stability, cycles, calibration to anchors, per-year/school/rotation/specialty results, reference/accepted coverage, abstention rate and the review workload. The implemented `metrics()` function covers tier/ranking metrics; reversed-order comparison is a separate operation. Report confidence intervals through paired item-level bootstrap, clustering related conditions and reviewers; at larger scale include school/region sensitivity. No bootstrap uncertainty is implemented in this small proof of concept.

Tentative operational goals to preregister, then confirm with stakeholders: ≥85% exact agreement, weighted kappa ≥0.80, no unreviewed Easy↔Hard errors and no materially worse core specialty subgroup. These are product goals, not medical education standards. Sparse strata remain unresolved even if the overall result passes. Holdout thresholds/weights must not be retuned until a new evaluation set is designated.

Luna is sufficient for a majority **only if** a prospectively evaluated routing policy accepts >50% of conditions while meeting the human-agreement targets on that accepted subset and the total pipeline, including its random audit. The present run cannot establish this. Terra earns its cost if its routing-policy arm yields a reproducible improvement versus Luna with matched human labels and source access, rather than simply moving scores. Track net corrections (fixed minus newly introduced errors), improvement on reviewed cases and across the whole bank, severe-error reduction, latency, tokens, human minutes and cost per additional correct label. A possible decision rule is ≥3 percentage points overall improvement or ≥20% reduction of errors in the routed subset at an agreed cost ceiling; preregister the ceiling and interval criteria before measuring. If source-poor cases stay unresolved, invest in Vietnamese evidence or human review rather than extra model calls.

No promotion/export command is included in v0.1. Once the reference and policy pass evaluation, review a complete candidate diff, approve a deterministic mapping to the game's existing H1–H5 schema, and preserve the runtime's strict allowlist. A possible compatibility mapping is Easy 0–15→H1 and >15–30→H2; Medium >30–60→H3; Hard >60–80→H4 and >80→H5, but this is unvalidated and would need sampling-distribution checks. Alternatively, migrate the public schema explicitly to three tiers in a separate change. Never quietly write 0–100 values into the existing 1–5 field or force equal tier sizes.

## Learning from future Chanle play

Current results are device-local aggregate statistics; there is no condition-level cohort telemetry suitable for calibration. A later opt-in data design should record pseudonymous participant, year, school/region at coarse granularity, rotation completion, condition ID, puzzle version, clinical/treatment mode, clue order and reveal timing, guesses, skips and correctness. Record autocomplete/assistance and selection probability, since the current difficulty sampler and specialty choices select nonrandom cases. No identifying patient or student information is needed.

Raw solve rate mixes familiarity with clue quality, audience ability and self-selection. Model each guess opportunity with a hierarchical logistic/IRT-style model including student ability/year/rotation, a shared condition-familiarity effect and separate mode/version/clue-step effects, plus exposure/repeat effects. Use several randomized clue orders/versions or a separate standardized familiarity quiz: one fixed puzzle per condition cannot identify condition familiarity separately from puzzle difficulty. Use failures, skips and censored attempts; do not fit only solved games. Keep first exposure separate from replay learning. Use randomized calibration slots or known propensity weights to address selection bias and partial pooling for sparse conditions. Validate on held-out students/conditions, stratify Y4–Y6, and report uncertainty before updating labels. Public clue performance alone should refine puzzle difficulty, not automatically overwrite the condition score.

## Running the proof of concept

All editorial data and responses remain in the existing ignored `.internal/` directory. A public clone includes tooling/prompts/tests, but not private sources or reference targets. The static preview server's file allowlist exposes none of these files. Back up the research directory separately; do not publish a whole local checkout.

```sh
# Requires the local reference/evidence packet prepared for this pilot.
deno run --allow-read --allow-write=.internal/condition-difficulty \
  scripts/condition-difficulty.js plan --model=luna --run=pilot-a

# Execute the packet with its stated native subagent model, then ingest JSON.
deno run --allow-read --allow-write=.internal/condition-difficulty \
  scripts/condition-difficulty.js ingest --plan=PATH_TO_PLAN --input=PATH_TO_RESPONSE

# The default evaluation intentionally fails until a human reference exists.
deno run --allow-read scripts/condition-difficulty.js evaluate --input=PATH_TO_CACHE

# Explicitly diagnostic only: agreement with the unvalidated seed targets.
deno run --allow-read scripts/condition-difficulty.js evaluate \
  --input=PATH_TO_CACHE --provisional

# Create pairwise packets in both orientations with different run labels.
deno run --allow-read --allow-write=.internal/condition-difficulty \
  scripts/condition-difficulty.js plan --model=luna --pair=1,35 --run=pair-forward
deno run --allow-read --allow-write=.internal/condition-difficulty \
  scripts/condition-difficulty.js plan --model=luna --pair=35,1 --run=pair-reverse
deno run --allow-read scripts/condition-difficulty.js pairs \
  --forward=FORWARD_CACHE --reverse=REVERSE_CACHE --absolute=ABSOLUTE_CACHE

deno task check
```

Production prompts: [`luna.md`](../scripts/difficulty/luna.md) and [`terra.md`](../scripts/difficulty/terra.md). Strict output schemas are exported from [`condition-difficulty.js`](../scripts/condition-difficulty.js) and embedded in each packet. [Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs) can enforce the schema in a future API transport, but refusal/truncation and semantic validation still require handling. The current native transport uses JSON plus local validation. Pilot caps prohibit more than 50 reference candidates and only the 12 designated pilot IDs are planned by default. There is deliberately no database-wide classify command.
